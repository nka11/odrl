Abstract

This specification is the Dataspaces binding of the Dialectical Ethical Profile for ODRL (core) [HEGEL-CORE]. The core defines hegel:EthicalCommitment, the six-state asynchronous PDP machine and the domain-neutral eth: ethics vocabulary without prescribing how identities, attestations, revocation or isolation are realised. This profile supplies those mechanisms for federated data spaces: W3C Decentralized Identifiers, W3C Verifiable Credentials 2.0 for ex-ante adhesion and ex-post inspection reports, W3C Bitstring Status Lists for O(1) gateway revocation, W3C PROV-O telemetry streaming, Trusted Execution Environments with cryptographic leases, and the platform ethics vocabulary (carbon intensity, sovereignty, open-source engines).

Status of This Document

This specification was published as a Draft Community Group Report for standardization discussion within the W3C ODRL Community Group and aligned with European federated data space initiatives (Gaia-X, DSSC, UNE 0087:2025). It is not a W3C Standard nor is it on the W3C Standards Track. It must be read together with the core specification. Contributions, ontology reviews, and reference implementation feedback are invited.

1.Introduction

Federated data spaces enable voluntary, sovereign data sharing among public administrations, private enterprises, and citizens under shared legal, organizational, and technical rules [UNE-0087]. The core profile expresses ethical commitments independently of any such infrastructure; this document states how a data space enforces and evidences them. The philosophical foundation (Creon / Antigone / Aufhebung) and the design principle of expressivity before enforcement are defined in the core and are not repeated here.

2.Conformance & Namespaces

Conformance terminology, the normative / non-normative convention and the BCP 14 key words are those of the core.

A conforming Dataspace Dialectical ODRL Policy MUST conform to the core profile [HEGEL-CORE], MUST declare the profile URI https://w3id.org/hegel-odrl/profile/dataspaces/v1/ via the odrl:profile property (which implies the core profile, prof:isProfileOf), and MUST realise every binding concern of core Section 5 as specified in Sections 3–5 of this document.

3.Dataspace Binding of the Core Model

The terms of the hegel: namespace are those of the core [HEGEL-CORE]. This section narrows them for federated data spaces; it adds no new states or transitions.

3.1Identities & Trust Registry

Parties (odrl:assigner, odrl:assignee), inspection oracles (hegel:inspectionSource) and deliberative bodies (hegel:deliberationTarget) MUST be identified by W3C Decentralized Identifiers (e.g. did:web). A hegel:deliberationTarget SHOULD be an instance of hegel-ds:FederatedEthicsCommittee, a subclass of hegel:DeliberativeBody operated by the data space federation. The federation MUST publish the DIDs of accredited oracles and committees, and the quorum rules of committees, in its Trust Registry (see Section 7).

3.3PDP State Guards (VC / Bitstring)

The six states, layers and transitions are those of the core. Here “attestation verified and not revoked” means a verified EthicalAdherenceCredential VP whose Bitstring Status List bit bi = 0, and “attestation revoked” means bi = 1. The table lists only the states whose guard or effect this binding specialises; hegel:PERMIT_UNCONDITIONAL is unchanged.

State (hegel:)Binding specialisation
hegel:DENYAlso entered when the assignee's status bit is revoked (bi = 1): the PEP checks this single bit in O(1).
hegel:PROVISIONAL_PERMIT_ATTESTEDRequires a valid EthicalAdherenceCredential VP and status bit bi = 0.
hegel:AUDIT_PENDINGPROV-O telemetry is streamed to hegel:inspectionSource; derived weights are held under hegel:cryptographicLease inside a TEE.
hegel:SUSPENDED_DELIBERATIONExit to hegel:PROVISIONAL_PERMIT_ATTESTED requires a favorable arbitral VC from the hegel:deliberationTarget.
hegel:REVOKED_ETHICAL_BREACHTriggers Bitstring revocation (bi = 1) and hegel:remedyProtocol.

5.Cryptographic Attestation, Provenance & Revocation

5.1Ex-Ante Adhesion (hegel:EthicalAdherenceCredential)

Before a PEP grants hegel:PROVISIONAL_PERMIT_ATTESTED, the consumer MUST present a W3C Verifiable Presentation containing a signed hegel:EthicalAdherenceCredential [VC-DATA-MODEL-2.0]. This shifts the burden of proof onto an indisputable cryptographic commitment tied to the policy hash and the consumer's DID.

5.2In-Itinere Lineage (W3C PROV-O) & Cryptographic Leases

During hegel:AUDIT_PENDING, the consumer's compute enclave MUST execute eth:emitProvenance, streaming signed W3C PROV-O assertions mapping input datasets (prov:Entity), training/inference runs (prov:Activity), human sign-offs (prov:Agent), and derived weights (prov:wasDerivedFrom) [PROV-O].

To prevent race conditions where a non-compliant model is exfiltrated before asynchronous audit completion, policies handling high-risk AI assets SHOULD pair eth:executionEnclave (eth:TEE) with eth:quarantineArtifact and a bounded hegel:cryptographicLease. Derived artifacts remain encrypted inside the enclave until the oracle emits a signed clearance heartbeat.

5.3Ex-Post Oracle Verdict & O(1) Bitstring Revocation

Upon concluding an inspection cycle (or detecting a threshold breach), the asynchronous oracle (hegel:inspectionSource) issues a hegel:InspectionReportCredential. If a substantive ethical breach is confirmed, the oracle flips the consumer's assigned bit in the W3C BitstringStatusListEntry from 0 to 1 [VC-BITSTRING]. On the next API request, the deterministic Creon PEP checks that single bit in O(1) time (≤ 5 ms) and immediately enforces hegel:DENY without performing heavy AI inspection in the network hot path.

7.Security, Privacy & Governance Considerations

The considerations of the core apply. This binding adds:

  • Exfiltration Race Conditions: Deployments processing high-impact assets SHOULD enforce eth:executionEnclave (eth:TEE) combined with eth:quarantineArtifact and hegel:cryptographicLease, and require eth:verifyEnclave attestation before hegel:PROVISIONAL_PERMIT_ATTESTED.
  • Telemetry Transport: PROV-O batches SHOULD be streamed over non-blocking channels (e.g., gRPC streams backed by columnar storage).
  • Revocation Registry Integrity: The Bitstring Status List MUST be published by a party the federation trusts, with a size large enough to preserve herd privacy of individual status indices, and PEPs SHOULD cache it within a bounded freshness window.
  • Trust Anchor for Deliberation: Federated data spaces implementing hegel:SUSPENDED_DELIBERATION MUST publish the institutional DID and multi-signature quorum rules of the hegel:deliberationTarget inside the federation's Trust Registry so arbitral VCs are cryptographically verifiable.
